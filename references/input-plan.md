# 卡通视频输入计划合同

## 用户输入与内部产物

用户可交一份或一批已确认定稿，并明确要求生产。Handler 内部必须为每稿生成独立 `content-plan.json`，不能让用户补 job、逐卡英文或批次清单。计划至少包含：

```json
{
  "schema_version": 1,
  "source_markdown_sha256": "当前原件的64位SHA256",
  "approved_by": "老大",
  "approved_at": "带时区的本轮明确授权时间",
  "title": "内容标题",
  "header": ["第一行", "第二行", "第三行"],
  "scenes": [
    {
      "id": "scene-01",
      "lines": ["第一张基础卡，", "第二张基础卡。"],
      "line_english": ["the first semantic line", "the second semantic line"]
    }
  ]
}
```

## Handler 生成计划的硬门

- 中文所有原始 `lines` 顺序拼接后，必须先与去掉 Markdown 展示符号的正文逐字一致；随后才允许生产层把精确 `3---12岁` 显示为 `3—12岁` 并逐项留痕。不得预先在计划中改成展示形式，不得转换其它年龄或连字符形式，也不得润色、删例子、泛化换标点或补营销句。
- 第一级 Markdown 标题作为文档标题不进配音；带完整口播信息的二级标题可以作为正文，纯标签小标题不进配音。
- 基础卡归一化后不超过24字；总控再无损拆成高复刻的10字目标、16字绝对上限。
- 每一条英文必须表达当前中文卡语义。允许上下卡组成连续英文短句；禁止 `Keep moving forward` 重复占位，禁止同一口号加 01/02/03。
- 三行标题必须是人类可读短句；总控仍会用真实 DOM 检查字号、自然字宽和 overflow。
- `approved_at` 只能记录当前对话中真实发生的明确授权；若用户只是让你讨论或预览方案，停在计划层，不生成配音。
- 生产前读取 `normalization-log.json.word_boundary_audit`。先尝试只移动相邻卡片边界并同步校正逐卡英文；调整前后中文拼接必须相同。无法无损消除的普通跨卡断句保留为 `WARN_WORD_BOUNDARY` 候选，不能擅改正文。


此文件只负责原稿与卡片输入。后续执行本 Skill 的生产合同；不要运行纸纹视频总控。
